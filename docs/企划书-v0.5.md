# M7H·ChestHunter 企划书 v0.5

> 《崩坏：星穹铁道》全宝箱半自治收集系统 —— 个人自用项目
> 基于 March7thAssistant（三月七小助手）**插件方式**扩展
> 版本历史：v0.2（骨架）→ v0.3（语义层+协议）→ v0.4（玩法核查修正）→ v0.5（知识/状态分离、Route Executor、指标化）

---

## 一、定位与原则

**攻略知识库驱动的半自治地图探索执行系统**——不做端到端 Agent。

三条铁律：
1. **运行时零 VLM**：所有视觉推理只在离线入库时发生一次。
2. **低置信知识禁止执行**：多维置信度，取 min 聚合（见 §六）。
3. **失败可分类、可恢复、可学习**（repair_log 反哺知识包）。

### 玩法事实核查表（沿用 v0.4）

| 企划假设 | 游戏实际 | 处理 |
|---|---|---|
| WASD 直线可走通 | 无攀爬，高台绕行；狭窄走廊易卡身位 | 路线是路径图；move 加 milestone 半程校验 |
| 移动速度恒定 | 冲刺无限、无体力条，sprint/walk 两档常数 | duration 线性换算；标注 speed |
| 视角固定 | 第三人称自由视角 | camera align 视觉伺服 + heading landmark |
| 每步结束可截图验证 | 动画/黑屏/加载时画面不可识别 | wait + find 兜底 |
| 画面恒定 | 剧情对话/UI 大改模板全失效 | dialogue 态检测 → autoplot |
| DB 状态即已收集 | 权威信号 = 小地图宝箱图标消失 | verify.minimap |
| 死了无影响 | 战斗失败 → 传回最近锚点 | respawn_route / back_landmark 两档 |
| 视频=完整路径 | 前置/限时未满足时宝箱不出现 | prerequisite 探测；timed 系数 |

## 二、系统架构

```
                攻略来源层  视频 / 图文 / 地图
                    ↓
                信息抽取层  VLM(离线) / 字幕OCR / 规则
                    ↓
      ┌──────── 知识层（文件包，Git 友好）────────┐
      │ knowledge/black_tower_v1/                │
      │  manifest.yaml / entities/ / workflows/  │
      │  templates/                              │
      └──────────────────┬───────────────────────┘
                         ↓
      ┌──────── 运行时（March7thAssistant 插件）──┐
      │ mission → route planner → route executor │
      │          → step executor → verify/recovery│
      └──────────────────┬───────────────────────┘
                         ↓
      runtime.db（progress / fail_log / repair_log / statistics / cache）
```

**v0.5 关键决策：知识/状态彻底分离**

| | 知识层 | 状态层 |
|---|---|---|
| 载体 | `knowledge/` 文件包（JSON/YAML/PNG） | `runtime.db`（SQLite） |
| 内容 | chests/landmarks/routes/workflows/templates | progress/fail_log/repair_log/statistics/cache |
| 用途 | git diff、回滚、分享、merge | 执行状态、统计、学习记录 |
| 更新方式 | 人工/管线落盘，可版本化 v1/v2 | 程序读写 |

> 攻略更新如 `move 3.2s → 3.5s`，git 天然适合 diff；DB 不存知识本体。

## 四、runtime.db Schema（状态库）

```sql
CREATE TABLE progress (            -- 断点续跑
  chest_id TEXT, route_id TEXT,
  step_index INT, last_landmark TEXT,
  autonomy_level INT, updated_at, UNIQUE(chest_id)
);

CREATE TABLE fail_log (
  id INTEGER PRIMARY KEY,
  chest_id, route_id, step_index,
  fail_type,                        -- position|template|combat|prerequisite|unknown
  screenshot_before TEXT, error_detail, retry_count, recovery_used
);

CREATE TABLE repair_log (          -- 错误学习（§七）
  id INTEGER PRIMARY KEY,
  chest_id, step_index,
  asset_kind,                      -- template|duration|threshold|route
  old_value TEXT, new_value TEXT,
  applied_to_version TEXT,         -- 知识包版本
  note TEXT, created_at
);

CREATE TABLE statistics (          -- 指标（§十三）
  id INTEGER PRIMARY KEY,
  entity,                          -- step|route|chest|mission
  entity_id, step_type,
  attempts INT DEFAULT 0, success INT DEFAULT 0,
  success_rate REAL GENERATED ALWAYS AS
    (CASE WHEN attempts>0 THEN success*1.0/attempts END),
  avg_time_s REAL, last_run_at
);

CREATE TABLE cache (               -- 截图/识别缓存
  key TEXT PRIMARY KEY, value TEXT, created_at
);
```

### 5.1 manifest.yaml

```yaml
  chests: entities/chests.json
  landmarks: entities/landmarks.json
  routes: entities/routes.json
workflows: workflows/
```

### 5.2 工作流 JSON（统一 schema_version）

```json
{
  "schema_version": "1.0",
  "chest_id": "black_tower_base_01",
  "confidence": { "location": 0.95, "route": 0.7, "interaction": 0.99, "prerequisite": 0.5 },
  "steps": [
    { "type": "move_hold", "data": { "keys": ["W"], "duration_s": 3, "speed": "sprint",
      "tolerance": { "max_drift": 0.5 } },
      "verify": { "milestone": "templates/m_l1.png", "timeout_ms": 60000 },
      "fail": "recovery" },
    { "type": "click_image", "data": { "template": "templates/interact.png" },
      "verify": { "minimap": "icon_absent", "timeout_ms": 15000 } }
  ]
}
```

### 5.3 步骤类型（协议 v1.0）

| type | data | 说明 |
|---|---|---|
| `move_hold` | `keys, duration_s, speed, tolerance.max_drift` | 移动；tolerance 允许漂移余量（§四建议） |
| `camera` | `mode:"rotate"` → `yaw_delta,pitch_delta,duration_s`；`mode:"align"` → `target:"landmark_007"` | 相对旋转 / **视觉伺服**（旋转→截图→直到 heading 对齐，§五建议） |
| `landmark` | `image, threshold, mode:"position"\|"heading"` | 平移/朝向校正 |
| `milestone` | `image, at_seconds` | 长 move 半程校验（>8s 必挂） |
| `click_image` | `template, anchor, repeat` | 复用 |
| `click_text` | `text\|regex, timeout` | 复用 |
| `find_image/find_text` | 同源 | 复用 |
| `dialogue` | `mode:"auto"` | 对话态 → autoplot |
| `condition` | `if:{...}, then, else` | 前置探测等 |
| `loop` | `until_condition, max_iters, body` | 机关 |
| `recovery` | `strategy:[...]` | 恢复通配 |
| `end` | `verify_method` | 收尾验证 |

## 六、多维可信度传播

```json
"confidence": { "location": 0.95, "route": 0.7, "interaction": 0.99, "prerequisite": 0.5 }
```

- 自动等级 = `min(confidence.*)`（低可信不掩盖）。
- 门禁：min < 0.5 → 禁止入任务列表；min < 0.6 → 仅人工模式。
- 各级指标来源：location=VLM+校验、route=route 执行统计回填、interaction=模板质量、prerequisite=探测验证。

## 七、错误学习闭环

```
fail_log 记录
   ↓
人工修复（新模板/调时长/改阈值）
   ↓
repair_log 记录 old→new + 目标知识包版本
   ↓
一键应用 → 生成知识包补丁（git commit）
   ↓
统计回填 → 系统越跑越稳
```

## 八、运行时状态机（第十二章）

```
        ┌──────────┐
        │   INIT   │ 读包/校验 schema/dry_run
        └────┬─────┘
             ↓
        ┌──────────┐      ┌─────────────┐
   ┌──► │NAVIGATING│────►│ VERIFYING   │
   │    └────┬─────┘      └──────┬──────┘
   │         ↑                   ↓
   │   ┌─────┴──────┐      ┌───────────┐
   │   │ RECOVERING │◄────│INTERACTING │
   │   └────────────┘      └─────┬─────┘
   │         ↑                   ↓
   │         │              ┌───────────┐
   │         └──────────────│   DONE    │
   │                        └───────────┘
   └── retry/back_landmark/respawn ──────┘
```

- 状态迁移由 step 结果驱动；每状态可挂超时与 recovery 分支。
- `RECOVERING` 内再做一次子状态分类（position/template/combat/prerequisite/unknown）。

## 九、Route Executor（核心新增，§三建议）

```
mission（区域任务：基座舱段全收集）
   ↓ route planner（知识包 routes + 统计排序）
route executor（一条路线执行）:
   Teleport(锚点)
    → Route A: 共用 landmark 走廊 → chest1 → chest2 → chest3
    → 统计回填 routes.json success_rate
   ↓ step executor（逐 step，dry_run 可插）
```

`entities/routes.json`：

```json
{
  "route_id": "base_floor_route_01",
  "start": "teleport_blacktower_base",
  "targets": ["black_tower_base_01", "black_tower_base_02", "black_tower_base_03"],
  "shared_landmarks": ["door_A", "corridor_B"],
  "attempt_count": 0, "success_count": 0
}
```

一次传送 → 连收多箱 → 每箱不重复校准。M4 再做 TSP 优化排序。

## 十、失败分类矩阵（规则，无 VLM）

| 失败信号 | 分类 | 恢复 |
|---|---|---|
| landmark/milestone 失配 | `position` | back_landmark |
| 目标连续 N 帧未命中 | `template` | 重截模板 → repair_log → 人工确认 |
| 战斗 UI 检出 | `combat` | 自动战斗 → 胜利继续；败 → respawn_route |
| 死亡/位置重置 | `position(respawn)` | respawn_route（起点锚点整段重跑） |
| 前置探测失败 | `prerequisite` | 标 unmet 跳过 |
| 其他/超时 | `unknown` | 中止 → 回放排查 |

## 十一、Dry Run 模拟执行（§十建议）

`dry_run=true`：不碰游戏，只读 JSON → 打印 `step1 move 3s → 验证milestone(m_l1.png) → step2 click...`，验证模板文件存在性与 schema。用途：知识包 CI 检查、防坏数据、新包冒烟。

## 十二、Evaluation System（第十三章）

| 指标 | 目标 | 测量 |
|---|---|---|
| Step success rate（分步型） | move ≥95% / click ≥98% / verify ≥95% | statistics 表按 step_type 聚合 |
| Task success rate | 10 箱 ≥80% | route 级聚合 |
| Recovery success rate | ≥50% | fail_log + recovery 结果 |
| Knowledge confidence | min ≥0.6 可自动 | 多维置信度 |
| Human intervention | 每路线 ≤1 次 | repair_log/人工确认计数 |
| Time per chest | ≤90s（L1） | statistics.avg_time_s |

验收逻辑：先定位"哪层失败"（步骤级），再谈任务级通过。

## 十三、插件架构（§十一拍板项 2）

**不改上游核心**。chest_hunter 作为独立插件：

```
March7thAssistant/            # 上游：黑盒平台
  module/automation/          # 复用：截图/输入/OCR/模板/日志/通知
        ▲ import
        │
chest_hunter/runtime/         # 自己实现步骤调度与状态机
  step_executor / route_executor / state_machine
  studio/                     # 自研 GUI（列表/详情/回放/dry_run）
```

- 上游更新 → git pull 即可，无需合并核心改动。
- 代价：workflow 引擎的 GUI 编辑/回放不可用 → Chest Studio 自研（M2）。
- 好处：module/automation 的 API 稳定（截图/点击/OCR 均为稳定接口），依赖面最小。
