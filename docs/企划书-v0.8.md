## 二、增量设计 1：Portal Transition

```json
{
  "id": "door_A",
  "type": "door",
  "transition": { "kind": "loading", "arrival_delay_s": 3 },
  "states": [
    { "name": "locked", "condition": "quest_research=false" },
    { "name": "open",   "condition": "quest_research=true" }
  ]
}
```

| transition.kind | 行为 |
|---|---|
| `instant` | 无等待，直接 arrival 判定 |
| `animation` | 开门动画 → wait 后 arrival |
| `loading` | 黑屏/加载 → 固定延迟 → 新房间检测 |
| `teleport` | 传送加载 → 新房间检测 |

过门动作序列：`click portal → PORTAL_TRANSITION(等待) → detect new room → arrival verify`。

状态机新增 `PORTAL_TRANSITION`（含超时与 recovery：重新点击/back_landmark）。

## 三、增量设计 2：Local Movement Policy

Room Graph 是语义层；运行层承认：没有导航 API，只有 WASD + 鼠标 + 视觉。

```json
{
  "edge": "corridor_A_to_elevator",
  "controller": {
    "type": "visual_follow",          // 跟随目标物移动
    "target": "lm_elevator",
    "max_time_s": 15,
    "heading_eligible": true,         // 适合 heading 伺服（门/电梯/明显建筑）
    "recovery": [ "reverse", "rotate_search", "back_landmark" ]
  }
}
```

- `visual_follow`：朝目标模板中心移动，定期（1-2s）重检目标位置纠偏。
- `heading_eligible=false` 时（空旷大厅/相似走廊/微调）：改用纯 landmark 节奏移动 + milestone 半程校验。
- 移动失败 → 按 recovery 序列：后退 → 原地旋转搜索 → 回最近锚点。

## 四、增量设计 3：execution context（world + player）

```
execution context = world_state + player_state
```

```json
// entities/player_states.json
{
  "in_combat": false,
  "in_dialogue": false,
  "menu_open": false,
  "team_ready": true,
  "dead": false
}
```

- 每次 EVENT_INTERRUPT 检测与 recovery 决策都读 player_state，避免误判（如"地图开着却当作卡住"）。

## 五、增量设计 4：Puzzle 降级为接口

```python
class PuzzleExecutor:
    def execute(solution: list[str]) -> bool: ...   # v1 仅 precomputed_sequence
    def verify(result) -> bool: ...
```

- **v1 只支持 `precomputed_sequence`**（人工录好的点击序列），不做 solver、不做状态建模。
- solver（rotation 等）M3 后再议；首批 puzzle 箱走人工预录序列。

```yaml
reward_type:   chest | reward | achievement        # 产出物类型
trigger_type:  normal | combat | quest | npc | environment | dynamic
```

## 七、增量设计 6：战斗 v1（最低姿态）

```
检测战斗 → EVENT_INTERRUPT(combat_random) → 暂停 → 等人工 → 恢复
```

- **v1 不做自动战斗**（崩铁战斗复杂度：弱点/队伍/战技点/秘技，污染项目）。
- L1/L2 均人工介入战斗，只保证"打完自动恢复原流程"。

## 八、增量设计 7：Knowledge Compiler

```
攻略视频 → VLM(事件描述) → raw events（半结构化）
    ↓ compiler（规则+校验+人工确认）
validated knowledge package（rooms/portals/chests/puzzles/…）
    ↓
runtime executable graph（含索引/统计/可达性）
```

```
ingest/
  raw/events/          # VLM 产出的半结构化事件
  compiler/
    build_rooms.py     # 事件 → 房间
    build_portals.py   # 事件 → portal/transition
    validate_graph.py  # 图连通/可达/门控一致性校验（dry_run 前置）
```

- compiler 是"人工维护痛苦"的收口：所有知识必须经 compiler 校验后才可入库执行。
