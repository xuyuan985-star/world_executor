## 〇、v0.6 核心定性

崩铁不是"开放世界"，是**箱庭地图 + 状态门控 + 交互节点网络**。

> 原神像自动驾驶汽车，崩铁像在机场航站楼走固定通道。
> 本系统应做"室内导航机器人"，不是"开放世界无人车"——难度大幅降低。

| 当前设计(v0.5) | 建议(v0.6) | 状态 |
|---|---|---|
| 二维坐标 position_lat/lng | **拓扑节点图 navigation_graph** | ✅ 采纳 |
| TSP 路线优化 | **传送点覆盖 + 图最短路径(Dijkstra/A*)** | ✅ 采纳 |
| duration 移动 | **目标节点移动 move.target + max_time** | ✅ 采纳 |
| 小地图图标绝对验证 | **多信号分级验证** | ✅ 采纳 |
| dialogue 自动处理 | **先 detect_only 暂停，L2 才 autoplot** | ✅ 采纳 |
| combat recovery 单独分支 | **统一事件中断 EVENT_INTERRUPT** | ✅ 采纳 |
| 宝箱数据无世界状态 | **world_state 门控** | ✅ 采纳 |
| chest_type 6 类 | **扩充 7 类** | ✅ 采纳 |

## 一、定位与原则

**攻略知识库驱动的半自治箱庭探索执行系统**——不做端到端 Agent，不做自由导航。

三条铁律：
1. **运行时零 VLM**；2. **低置信知识禁止执行**（min 聚合）；3. **失败可分类、可恢复、可学习**。

## 四、navigation_graph（拓扑节点图）

### 4.1 建模（替换坐标空间）

```json
// entities/navigation_graph.json
{
  "nodes": [
    { "id": "teleport_base",        "type": "teleport" },
    { "id": "corridor_A",           "type": "corridor",  "landmark": "lm_corridor_a" },
    { "id": "elevator_room",        "type": "room",      "landmark": "lm_elevator" },
    { "id": "research_door",        "type": "door",      "landmark": "lm_research_door" },
    { "id": "sealed_room",          "type": "room",      "landmark": "lm_sealed" }
  ],
  "edges": [
    { "from": "teleport_base", "to": "corridor_A",     "cost": 12, "requires": null },
    { "from": "corridor_A",    "to": "elevator_room",  "cost": 8,  "requires": null },
    { "from": "corridor_A",    "to": "sealed_room",    "cost": 8,  "requires": "quest_research" },
    { "from": "elevator_room", "to": "research_door",  "cost": 5,  "requires": null }
  ]
}
```

- **chests.node_id** 替代 position_lat/lng（例：`node_id: corridor_A`）。
- 边带 `requires`（世界状态门控）与 `cost`（图搜索用）。
- 导航 = 图上的边序列；每条边的实际行走由"move.target + landmark 伺服"完成。

### 4.2 图导航与传送覆盖（替代 TSP）

```
传送点覆盖：一次传送 → 覆盖可达节点子图 → 区内节点用图最短路径(Dijkstra/A*)
目标：最小化传送次数 + 图边总 cost
```

删除 TSP（适合连续二维空间，不适用箱庭）。

## 五、知识包 Specification

### 5.1 manifest.yaml（含世界状态门控）

```yaml
package: black_tower_v1
region_id: black_tower
game_version: "2.x"
schema_version: "1.0"
world_state:                      # 区域级前提
  main_quest: "已完成·重返黑塔"
  time: null                      # 崩铁无昼夜；保留字段备用
confidence: { location: 0.9, route: 0.8, interaction: 0.9, prerequisite: 0.7 }
entities: { world_states, navigation_graph, landmarks, routes, chests }
workflows: workflows/
```

### 5.2 工作流 JSON

```json
{
  "schema_version": "1.0",
  "chest_id": "black_tower_base_01",
  "node_id": "corridor_A",
  "chest_type": "normal",
  "confidence": { "location": 0.95, "route": 0.7, "interaction": 0.99, "prerequisite": 0.5 },
  "steps": [
    { "type": "move",
      "data": { "target": "corridor_A", "max_time_s": 10, "speed": "sprint",
                "fallback": "milestone" } },
    { "type": "click_image", "data": { "template": "templates/interact.png" } },
    { "type": "end",
      "verify": {
        "primary":   { "minimap": "icon_absent" },
        "secondary": { "animation": "templates/chest_open.png" },
        "tertiary":  { "text": "获得战利品" } } }
  ]
}
```

### 5.3 步骤类型（协议 v1.1）

| type | data | 说明 |
|---|---|---|
| `move` | `target:node_id, max_time_s, speed, fallback:milestone` | **目标节点移动**；duration 仅是执行参数，不是目标（§六） |
| `camera` | `mode:"rotate"` yaw/pitch delta；`mode:"align"` → target landmark | 视觉伺服 |
| `landmark` | `image, threshold, mode:"position"\|"heading"` | 沿边伺服核心 |
| `milestone` | `image, at_seconds` | 长边半程校验 |
| `click_image/click_text/find_image/find_text` | 复用 | 复用 |
| `dialogue` | `mode:"detect_only"`（默认）\| `mode:"autoplot"`（L2 后） | **先暂停检测，不自动点**（§七修正） |
| `condition` | `if:{world_state/*,image,text}, then, else` | 门控与前置探测 |
| `loop` | `until_condition, max_iters, body` | 机关 |
| `recovery` | `strategy:[...]` | 恢复通配 |
| `end` | `verify:{primary,secondary,tertiary}` | 多信号收尾 |

## 六、多信号验证（小地图降级为 primary，非唯一）

```
verify:
  primary:   minimap / 开箱动画     # 主信号
  secondary: 交互结果 / 机关完成    # 兜底
  tertiary:  文本(获得战利品)       # 最终兜底
```

- **普通箱**：开箱动画 + 地图统计变化
- **机关箱**：机关完成 + 宝箱出现 + 开箱动画
- **任务箱**：任务状态变化（world_state 更新）
- 判定规则：primary 通过 → DONE；primary 未通过但 secondary+tertiary 通过 → DONE 并记低置信；全不通过 → fail。

## 七、事件中断 EVENT_INTERRUPT（统一暂停导航）

```
NAVIGATING / INTERACTING
        │ 检测到外部事件
        ▼
   EVENT_INTERRUPT
   ├── combat     （回合制战斗：进入后地图暂停）
   ├── dialogue   （detect_only：暂停等人工/或L2 autoplot）
   ├── cutscene   （剧情演出：等待结束）
   └── ui         （弹窗/任务面板/结算：分类处理）
        │ 事件结束
        ▼
   RESUME（回到断点状态继续）
```

战斗不再是"移动异常"，而是导航暂停事件；失败/团灭才进入 recovery。

## 九、world_state 世界状态（v0.6 最大缺口补全）

```json
// entities/world_states.json
{
  "quest_research": { "type": "quest_done", "quest_id": "人非草木·其一", "note": "任务完成后封闭门开启" },
  "daily_vendor":   { "type": "daily_refresh", "note": "每日4点刷新" },
  "npc_present":    { "type": "npc_available", "npc": "阿兰" }
}
```

- 区域执行前：先跑"世界状态探测"（OCR 任务面板/小地图/条件交互），失败 → 标 `prerequisite_unmet` 跳过，**不反复尝试不存在的箱子**。
- 图边 `requires` 与 chest `prerequisite` 引用同一 world_state 键。

## 十、失败分类矩阵

| 失败信号 | 分类 | 恢复 |
|---|---|---|
| landmark/milestone 失配 | `position` | back_landmark（最近锚点） |
| 目标连续 N 帧未命中 | `template` | 重截 → repair_log → 人工确认 |
| 战斗团灭/位置重置 | `position(respawn)` | respawn_route（传送锚点整段重跑） |
| 事件中断未结束（超时） | `interrupt` | 重探测事件类型 → 人工 |
| 世界状态探测失败 | `prerequisite` | 标 unmet 跳过 |
| 其他/超时 | `unknown` | 中止 → 回放排查 |

## 十一、运行时状态机（v0.6）

```
        INIT → CHECK_WORLD_STATE（门控）
               ↓ pass
        NAVIGATING ──┐    （Graph Navigator 沿边移动）
               ↓     │ 检测到外部事件
        VERIFYING    │
               ↓     │
        INTERACTING──┤
               ↓     ▼
        DONE ←── EVENT_INTERRUPT(combat/dialogue/cutscene/ui)
                    ↓ 结束
               RESUME（回到中断前状态）
                    ↓
        RECOVERING（fail 后：分类→恢复→回断点）
```

- 状态迁移由 step 结果 + 事件探测驱动；EVENT_INTERRUPT 是横切状态，任何执行态都可能进入。
- RECOVERING 内做子分类（position/template/interrupt/prerequisite/unknown），恢复后回断点或 abort。

   → 统计回填 → 越跑越稳

## 十三、Evaluation System

| 指标 | 目标 | 测量 |
|---|---|---|
| Step success rate（分步型） | move ≥95% / click ≥98% / verify ≥95% | statistics 按 step_type 聚合 |
| Task success rate | 10 箱 ≥80% | route 级聚合 |
| Recovery success rate | ≥50% | fail_log + 恢复结果 |
| Interrupt 处理率 | 战斗/对话打断后成功续跑 ≥80% | EVENT_INTERRUPT 记录 |
| Knowledge confidence | min ≥0.6 可自动 | 多维置信度 |
| Human intervention | 每路线 ≤1 次 | repair_log/人工确认计数 |
| Time per chest | ≤90s（L1） | statistics.avg_time_s |

验收逻辑：先定位"哪层失败"（步骤级），再谈任务级通过。

## 十四、Dry Run 模拟执行

`dry_run=true`：不碰游戏，只读知识包 → 沿图模拟走查（打印 `edge corridor_A→elevator_room cost 8 → step move(3s) → verify...`），校验 schema/模板文件存在性/图连通性。用途：知识包 CI、防坏数据、新包冒烟。

## 十七、MVP 里程碑（v0.6 修正）

### Sprint 0：三个状态，不是三个宝箱

| 用例 | 验证点 | 覆盖复杂度 |
|---|---|---|
| Case 1 普通箱 | move(节点) + click + 多信号 verify | 基线执行 |
| Case 2 锁怪箱 | **EVENT_INTERRUPT(combat)**：进战→自动战斗→退战→续跑 | 事件中断 |
| Case 3 前置箱 | **world_state 门控**：探测→unmet 跳过 / pass 执行 | 状态门控 |

> 这三个覆盖崩铁 90% 复杂度。通过后架构成立，扩地图只是数据量。

| 里程碑 | 内容 | 验收 |
|---|---|---|
| Sprint 0 | 知识包 v1 规范 + 协议 v1.1 + 状态机骨架 + dry_run + 三用例手写包 | 三用例通过 dry_run |
| M0 数据链 | fetch→frames→classify→vlm→structure→verify_cli | "三重权限"片 → 产出三用例知识包并通过 dry_run |
| M1 执行器 | graph_navigator + route_executor + interrupt 处理 + 断点续跑 | 步骤级 move≥95%/click≥98%/verify≥95%；任务级 10 箱≥80%；朝向随机连跑 3 次 |
| M2 知识库+Studio | runtime.db 全 DDL + 回放/编辑 GUI + repair 闭环 | Recovery ≥50%；一次模板修复可重跑 |
| M3 黑塔全图 | 9P 入库（v1 包） | 空间站收集率 ≥90%（L1） |
| M4 扩展 | 多地图、传送覆盖+图搜索优化、探索度同步 | 仙舟试点 |

**Sprint 0 铁律：只做黑塔基座舱段，不扩地图。**
