## 一、ActionIntent 抽象（坐标是执行细节，不是动作语义）

### 1.1 问题

`backend.click(x, y)` 让 runtime 继续接触坐标/DPI/screenshot_pos——v0.12 刚把它们踢出执行器，不能从输入层漏回来。

### 1.2 设计

```
Decision
   ↓
ActionIntent { action, target, method, params, reason }
   ↓
InputBackend.execute(intent)
   ↓
March7th Driver
```

```python
@dataclass
class ActionIntent:
    action: str        # interact | click_text | move | press_key
    target: str        # 知识包目标 id / 模板文件名 / 文字 / 按键
    method: str        # template | text | key（VLM 定位坐标由 observation 携带，不进 intent）
    params: dict       # max_retries / threshold / include / crop / wait_time
    reason: str        # 决策意图（objective_verify_chest …）
    source: str        # decision_layer | manual | recovery
```

- **决策层永远不产生坐标**。VLM 定位结果（0-1000 归一化）只进 observation 事件；executor 消费"最近的 vlm 定位观测"换算绝对坐标（换算属于执行细节，留在 executor/driver 层）。
- `interact_template` / `click_text` 改为 `executor.execute(intent)`，输入失败返回 `InputResult`（backend/success/error 不变）。

## 三、Input Health L0-L2（避免"光标能动=输入可用"的假通过）

健康检查拆三层，M1 前必须 L0+L1 通过，L2 尽力（游戏在时必查）：

| 层 | 检查 | 通过条件 | 失败含义 |
|---|---|---|---|
| L0 cursor_move | SetCursorPos → GetCursorPos 回读 | 落点一致 | 注入通道被拒（UIPI） |
| L1 send_input | SendInput 注入事件返回 | ret == 数量 | 输入事件级被拒（需提权） |
| L2 game_response | 按 ESC → 截图 → 画面变化/OCR 命中菜单词 | 变化显著或命中"设置/菜单/ESC 提示" | **游戏忽略输入**（焦点错/游戏无响应） |

- L2 失败**阻止 mission 开始**（v0.11 附录 G pause + human check）。
- L0/L1/L2 结果进 `capability` 字典 + GUI `RuntimeHealthBar`（输入权限一栏显示 L0/L1/L2 分级结果）。

## 四、Emergency Pause（人工安全刹车，M1 默认开启）

**不是功能，是工程保护**：任何"人接手了电脑"的信号 → 立即暂停，绝不继续执行。

```python
runtime/safety.py  # EmergencyMonitor（后台线程，0.5s 轮询）
```

触发条件（任一）：

- 用户移动鼠标（光标偏离"上次自控位置"超过阈值）→ `reason=cursor_moved`
- 前台窗口切离游戏窗口 → `reason=window_switch`
- 游戏状态异常（health L2 突变 / 截图通道失败连续 N 次）→ `reason=state_anomaly`

动作：

```
emit human_intervention { reason, detail }   # 事件类型新增
emit pause_requested     { reason: human_intervention }
```

- GUI 指挥台 LED 转"⚠ 人工介入"，等待人工确认恢复（RESUME_CHECK 强制重校验，附录 G 不变）。
- EmergencyMonitor 在 mission start 时启动、finish 时停止；M1-A 阶段强制开启。

## 五、Failure Category 固化（F1/F2/F3 自动分类）

Deterministic Failure Replay（v0.12 §5.2）的 diff 结果直接落分类：

| 类别 | 判据 | 例子 | 修复方向 |
|---|---|---|---|
| F1 输入失败 | same observation / action failed | 看到箱子，点击失败 | input（提权/焦点） |
| F2 视觉漂移 | same action / different observation | 第一次看到箱子，第二次没看到 | observer（模板/VLM/时序） |
| F3 决策漂移 | different action / same observation | 同样画面，选择不同路径 | decision（规则/状态机） |
| unknown | 无法归类 | — | 人工 |

- `fail_recorded` 事件 context 增加 `category`；failure_reports 证据包文件名带类别。
- GUI Failure Inspector 显示 `[F1 输入失败]` 徽标。

## 六、Temporal Stability 确认（majority_vote，不复杂化）

v0.12.1 明确：M1 阶段一致率算法 = **majority_vote**（现有 sample_stability 已是 Counter 多数表决）。

- 3 次 `absent/absent/present` → `decision=absent, stable=false`（66% < 75%）
- 5 次 `absent×4, present×1` → `decision=absent, stable=true`（80% ≥ 75%）

**不引入** embedding similarity / 时间模型 / Kalman。
