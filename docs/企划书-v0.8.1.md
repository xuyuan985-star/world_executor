## 一、补丁 1：Portal Transition 失败出口（必须）

高频现实：点击门 → 没反应 → 仍在原房间（距离不够/角度不对/NPC 或空气墙挡/交互按钮未出现）。

```json
{
  "id": "door_A",
  "type": "door",
  "transition": { "kind": "loading", "arrival_delay_s": 3 },
  "portal_fail_policy": [
    "retry_interact",      // 重试点击交互
    "adjust_position",     // 微调站位（左右/前后短移）
    "reacquire_heading",   // 重新 heading 校准（面向门）
    "abort"                // 放弃 → fail_log
  ]
}
```

- 状态机新增 **PORTAL_TRANSITION_FAILED**：按 policy 逐级尝试，全部失败才进入 fail_log（**不直接进 UNKNOWN**）。

---

## 二、补丁 2：Local Movement Policy 降级为 visual_guided_move

第三人称镜头：**屏幕中心 ≠ 世界前方**（背身/贴墙/目标在侧面时持续按 W 会撞墙）。

v1 禁止"看到目标 → 持续 W"的长时间驾驶；改为**短步移动**：

```json
{
  "type": "move",
  "controller": {
    "type": "visual_guided",       // 替代 visual_follow
    "tick_interval_s": 1.5,        // 每步间隔
    "max_forward_s": 2,            // 单次前进上限 2 秒
    "recheck": true                // 每步后重检目标
  },
  "recovery": ["reverse", "rotate_search", "back_landmark"]
}
```

循环：`目标检测 → 计算偏差 → 调整镜头 → 短移动(≤2s) → 重检`。宁可慢，不可撞。

## 三、补丁 3：State Observation Model（事实 vs 检测值）

运行时不存"结论"，存"观测"：

```json
{
  "state": "portal_open",
  "value": true,
  "observer": { "type": "template", "id": "door_open_01" },
  "confidence": 0.98,
  "time": 123456
}
```

- 所有状态（in_combat/in_dialogue/menu_open/portal_open/arrival）统一为观测模型：`value + source(OCR/template/UI/inferred) + confidence + time`。
- 作用：debug 回答"为什么系统认为门开了/脱离战斗/进入房间"；recovery 决策可查置信度。

## 六、补丁 6：runtime.db 增加 state_observation 表

```sql
CREATE TABLE state_observation (
  id INTEGER PRIMARY KEY,
  state_type TEXT,        -- combat|dialogue|menu|portal|arrival|world
  state_key TEXT,         -- 'in_combat' / 'door_A.open'
  value TEXT,             -- 'true'/'false'/'open'...
  observer_type TEXT,     -- template|ocr|ui|inferred|manual
  observer_id TEXT,
  confidence REAL,
  created_at
);
```

- 全表 = 可审计的"为什么"日志；recovery 与 World Studio 调试均依赖它。
