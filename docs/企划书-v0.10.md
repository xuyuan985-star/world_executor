## 一、状态机显示层压缩（GUI 层）

**runtime 状态机冻结不动（v0.8.1）**；GUI 显示层压缩为 8 个主状态泳道：

```
INIT → CHECK_CONTEXT → NAVIGATING → PORTAL_TRANSITION → INTERACTING → VERIFYING → DONE
                          ↖________________ RECOVERING ________________↙
```

- 主泳道 8 个：INIT / CHECK_CONTEXT / NAVIGATING / PORTAL_TRANSITION / INTERACTING / VERIFYING / RECOVERING / DONE。
- **overlay 事件**（不占泳道，作为当前状态上的浮动徽标 + 迁移日志行）：
  - combat（战斗中断）
  - dialogue（对话中断）
  - portal_failed（传送门失败→RECOVERING）
  - event_interrupt（异常中断→RECOVERING）
- ABORT 不画入泳道（红色终止横幅）。
- 触发条件：runtime 事件中 `EVENT_INTERRUPT` / `PORTAL_TRANSITION_FAILED` → GUI 映射为 overlay 徽标并自动指向 RECOVERING。

## 二、World Graph View（不是地图）

崩铁地图非连续空间（房间/电梯/走廊/传送点），Room+Portal 结构图比游戏小地图更接近真实。

- **命名铁律**：Graph View，不叫 Map。
- 节点：房间（RoundRect 卡片 + 观察模板缩略图）；边：Portal（青金连线 + transition 类型）。
- 右上角 **Abstraction Level** 切换器：
  ```
  [Room]  ← 房间节点 + Portal 边（默认）
  [Portal] ← 只看传送门拓扑
  [Objective] ← 房间内目标（宝箱/事件点）散布视图
  ```
- 不渲染二维地图坐标。

## 三、Runtime Replay（新增·v0.9 缺失的最大功能）

目标不是录屏，是**执行轨迹回放**：每次 run 的完整状态变化 + 观测 + 动作 + 失败点。

```
Run #001
00:00  INIT
00:03  room=corridor_A  confidence=0.92     [observation]
00:08  portal_A detected                    [observation]
00:10  transition                           [state]
00:15  arrival failed                       [state → RECOVERING]
00:16  recovery: back_landmark              [action]
00:21  reacquire_heading                    [action]
00:30  room=room_B  success                 [state → DONE]
```

- 数据源：runtime.db（progress + state_observation + fail_log + repair_log + statistics 五表联查，按 execution_id）。
- GUI：Run 列表（execution_id + 目标 + 起止时间 + 结果）→ 选中后时间线播放（步进/自动播放/跳转到失败点）。
- 价值定位：维护执行系统，而非制作工具。
- 落地：GUI-M0.3（与观测页共享数据层）。

## 四、Knowledge Package Version Panel

知识包 = 软件版本，必须自描述：

```json
{
  "protocol": "1.3",
  "package_id": "black_tower_v1",
  "schema": "1.3",
  "compiled_by": "manual",
  "compiled_at": "2026-08-08",
  "verified": true,
  "runtime_compatible": true
}
```

- 每个知识包根目录 `package.json`（validator 强制检查，缺失 = error）。
- 知识库页增加 **Package Version Panel**：显示 package_id / schema / compiler 日期 / verified / runtime compatible，并检查"runtime v1.x ↔ 知识包 schema 兼容"。
- 防止未来 runtime v1.5 + knowledge v1.1 + template v0.8 混乱。

## 六、runtime/api 单向依赖层（防 GUI 绑架 runtime）

```
runtime/
  api/
    events.py     # 事件总线：state_changed / observation / run_started / run_finished
    commands.py   # start_mission / pause / stop / inspect / replay
  state_machine.py（冻结不动）
  step_executor.py（M0）
```

- **单向**：runtime →（事件）→ GUI；GUI →（仅 api commands）→ runtime。
- GUI 禁止 import route_executor / step_executor / state_machine 内部。
- CLI、测试、自动运行全部走同一 api 层，不被 GUI 绑架。

## 七、Sprint 0 执行顺序修订（审查后唯一路径）

```
1. Smoke Test March7th API（截图/点击/OCR，需游戏窗口）
2. runtime/api/events.py 事件总线（dry_run 接入发事件）
3. dry_run 通过事件总线输出轨迹
4. GUI 监听事件显示（先丑后美，UI 骨架不接 runtime 不启动）
```

**顺序铁律：runtime 吐事件 → GUI 显示事件。禁止先画 UI 再接 runtime。**

三现实验证（冻结后只验证，不再加功能）：
1. March7thAssistant 自动化接口能否稳定控制崩铁窗口
2. 视觉伺服能否在一个黑塔房间跑通
3. 一个知识包从人工制作到执行闭环是否成立
