# M7H·ChestHunter 企划书 v0.4

> 《崩坏：星穹铁道》全宝箱半自治收集系统 —— 个人自用项目
> 基于 March7thAssistant（三月七小助手）扩展
> 版本历史：v0.2（骨架）→ v0.3（语义层+协议）→ v0.4（玩法核查修正）

---

## 一、定位与原则

**攻略知识库驱动的半自治地图探索执行系统**——不做端到端 Agent。

```
输入：攻略知识 → 理解/转换 → 执行 → 校验 → 修正 → 输出：收集进度
```

三条铁律：

1. **运行时零 VLM**：所有视觉推理只在离线入库时发生一次；运行时只读结构化 JSON + 本地模板匹配。
2. **低置信知识禁止执行**：知识分级，未达门槛的宝箱只允许人工模式。
3. **失败可分类、可恢复、可回放**：无人值守的决定性因素。

### 玩法事实核查表（v0.4 修正依据）

| 企划假设 | 游戏实际 | 处理 |
|---|---|---|
| WASD 直线可走通 | 无攀爬/跳跃翻越，高台必须绕行；狭窄走廊/门框/楼梯易卡身位 | 路线是路径图；move 段加半程里程碑 |
| 移动速度恒定 | 冲刺无限、**无体力条**（速度常数为 sprint/walk 两档） | duration 线性换算可靠；标注 speed 即可 |
| 视角固定 | 第三人称视角可任意旋转 | landmark 增加 heading（朝向）校正 |
| 每步结束可截图验证 | 开箱动画/黑屏过渡/加载时画面不可识别 | wait + find 兜底步骤 |
| 画面恒定 | 剧情对话/UI 大改时模板全失效 | 对话态检测 → 复用 autoplot |
| DB 状态即"已收集" | 权威信号 = 小地图宝箱图标消失 | verify.minimap 类型 |
| 死了无影响 | 战斗失败 → 传送回最近锚点 | recovery 分 respawn_route / back_landmark 两档 |
| 视频=完整路径 | 限时/前置条件/世界状态未满足时宝箱不出现 | prerequisite 探测步骤；timed 安全系数 |

## 二、系统架构

```
                攻略来源层  视频 / 图文 / 地图
                    ↓
                信息抽取层  VLM(离线) / 字幕OCR / 规则
                    ↓
               ┌ 地图语义知识层 ────────────────┐
               │ regions │ landmarks │ routes │
               │ chests(位置/类型/难度/前置)   │
               └──────┬────────────────────────┘
                      ↓ (知识 JSON 包 + 模板图)
               Workflow 执行层
               动作(move/camera/click) │ 校验(验证图/文本/landmark/小地图) │ 恢复(recovery)
                      ↓
               进度跟踪 / 失败分类 / 日志 / 断点续跑
```

设计决策：

- **知识资产 = 文件包为主**（Git 友好、可 diff、可版本化），DB 只做执行期状态：索引、进度、成功/失败统计、日志。
- 引擎复用 March7thAssistant 的 `module/workflow` 能力（截图/OCR/模板匹配/输入/通知/日志），仅注册新增步骤类型。
- 运行时 100% 确定性执行：每步有终止条件、超时、失败策略；无概率推理。

## 四、SQLite Schema（状态库）

```sql
CREATE TABLE regions (
  region_id TEXT PRIMARY KEY,        -- 'black_tower'
  name TEXT, floor_count INT,
  knowledge_version TEXT,            -- 'v1'/'v2'
  unlock_quest TEXT,                 -- 前置任务
  status TEXT DEFAULT 'unregistered' -- unregistered/ready/collecting/done
);

CREATE TABLE chests (
  chest_id TEXT PRIMARY KEY,         -- 'black_tower_floor1_01'
  region_id TEXT NOT NULL,
  floor_id TEXT,                     -- 'base'/'contain'/'support'/'confine'
  name TEXT,
  position_lat REAL, position_lng REAL,   -- 攻略图坐标（预留）
  chest_type TEXT,                   -- normal|puzzle|quest|hidden|timed|combat
  difficulty INT DEFAULT 1,          -- 1普通 2有机关 3解谜 4任务链 5隐藏
  prerequisite TEXT,                 -- 前置条件描述
  source_url TEXT, source_time TEXT,
  knowledge_version TEXT,
  confidence REAL,                   -- 0.0-1.0
  status TEXT DEFAULT 'pending',     -- pending|verified|collected|failed|prerequisite_unmet
  steps_json TEXT,                   -- 步骤协议（§五）
  verify_method TEXT,                -- image|text|landmark|minimap
  collected_count INT DEFAULT 0,
  FOREIGN KEY(region_id) REFERENCES regions
);

CREATE TABLE landmarks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  region_id, name, image_path,
  landmark_type TEXT,                -- elevator|door|teleport|npc|corner
  has_heading INT DEFAULT 0,         -- 是否带朝向模板（S1）
  position_x, position_y,
  knowledge_version
);

CREATE TABLE routes (
  route_id INTEGER PRIMARY KEY,
  region_id,
  start_anchor TEXT,                 -- teleport_anchor | landmark 名（A8）
  from_landmark, to_landmark,
  actions_json,
  distance_hint,
  attempt_count DEFAULT 0, success_count DEFAULT 0
);

CREATE TABLE progress (              -- 断点续跑
  chest_id, step_index, last_landmark,
  autonomy_level, updated_at,
  UNIQUE(chest_id)
);

CREATE TABLE fail_log (
  id INTEGER PRIMARY KEY,
  chest_id, step_index,
  fail_type,                         -- position|template|combat|prerequisite|unknown
  screenshot_before, timeout_stamp,
  retry_count, recovery_used
);
```

**置信度门禁**：`confidence < 0.6` 只允许人工模式；`< 0.5` 禁止进入任何任务列表。

## 五、Step 协议规范

统一结构：

```json
{
  "type": "move_hold",
  "data": { ... },
  "verify": { "image|text|landmark|minimap": "...", "timeout_ms": 60000 },
  "fail": "recovery|abort",
  "step_timeout_ms": 30000
}
```

### 步骤类型表

| type | data 字段 | 说明 |
|---|---|---|
| `move_hold` | `keys:["W"], duration_s, speed:"sprint"\|"walk"` | 崩铁 WASD 相对朝向移动；速度恒定两档（S2） |
| `camera` | `yaw_delta, pitch_delta, duration_s` | 相对角旋转，不写绝对角 |
| `landmark` | `image, threshold:0.85, mode:"position"\|"heading"` | 平移校正 / 朝向校正（S1）；mode=heading 时以"所见即锚点视角"为终止 |
| `milestone` | `image, at_seconds` | 长 move 段中途半程校验点（S5，move>8s 必挂） |
| `click_image` | `template, anchor:"center", repeat` | 复用 workflow |
| `click_text` | `text\|regex, timeout` | 复用 workflow |
| `find_image/find_text` | 同源 | 复用 workflow |
| `dialogue` | `mode:"auto"` | 对话态检测：进入剧情 → 启用 autoplot → 结束继续（A6） |
| `condition` | `if:{text/image/landmark/minimap}, then, else` | 检查类（含前置探测 A7） |
| `loop` | `until_condition, max_iters, body:steps[]` | 机关/重复交互 |
| `recovery` | `strategy:[open_map, teleport, back_landmark, respawn_route]` | 恢复通配（A8） |
| `end` | `verify_method` | 收尾验证 |

### 失败分类矩阵（规则，无 VLM）

| 失败信号 | 分类 | 恢复 |
|---|---|---|
| landmark/milestone 匹配失败 | `position` | `back_landmark`（轻微漂移，回最近锚点） |
| click 目标连续 N 帧未命中 | `template_expired` | 重截模板 → 建议人工确认 → 更新知识包 |
| 战斗 UI 检出 | `combat` | 自动战斗开关 → 胜利后继续；失败 → `respawn_route` |
| 死亡/传送后位置重置 | `position(respawn)` | `respawn_route`：从 route 起点锚点整段重跑 |
| 前置条件探测失败 | `prerequisite` | 标记 `prerequisite_unmet` 跳过，不盲目执行 |
| 其他/超时 | `unknown` | 中止 → 断点记录 → 人工查回放 |

## 六、预处理管线（视频 → 知识包）

```
① 拉取   B站 API 拿 BV/cid/分P → 下载 → 本地 mp4
② 抽帧   1fps 均匀 + 场景差分关键帧 → ~180帧/170s；字幕提取（优先B站轨，缺则屏幕OCR）
③ 分类   scene_classify → move/puzzle/ui/chest/combat/plot 段（字幕时间轴+帧聚类切段）
④ 分镜   VLM 逐批理解：帧序列+字幕+上段摘要 → 叙述剧本（上下文协议防漏帧；失败重试1次后标人工）
⑤ 结构化 叙述 → chest JSON（本地规则抽取 + 二次 VLM 校准；标注 speed/timed系数/前置）
⑥ 校验   校验卡：每步前后截图×2 + 描述 + 终止条件，人工勾"对/改"（1-3分钟/条）
⑦ 入库   templates/ 存锚点图+小地图图标；landmarks/routes 落盘；DB 状态就绪
```

**成本口径**（实测 BV1YM4y1a7wf：9P/1488s/1080p）：

| 对象 | 成本 |
|---|---|
| 单条 170s 视频 | ¥0.2（flash 档）～ ¥0.9（常规档） |
| 全 9P 一次入库 | ¥5–8 |
| 字幕 OCR（RapidOCR 本地） | 0 |

单条成本结构：VLM 分镜 85% / 二次结构化 10% / 重试 5%。

## 七、安全三档（autonomy_level）

- **L0**：只显示"[下一步: 向前3秒 + 右转]"提示，人手操作
- **L1**（默认）：移动/镜头自动，每步交互前弹人确认
- **L2**：全自动（需 chest confidence ≥ 0.8 且知识包 verified）

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| 移动漂移/卡墙（核心） | milestone 半程校验 + back_landmark |
| 朝向不确定（核心） | heading 型 landmark + camera-until-match |
| 模板失效（版本 UI 改） | template_expired 分类 + 重截 + 知识版本 v1/v2 |
| 攻略漏/过时宝箱 | 小地图图标扫描补充发现（远期）；探索度% OCR 比对 |
| VLM 对指令幻觉 | 两步结构化：只出叙述文本，不出 JSON 步骤 |
| 游戏内异常 | 对话态检测 / 战斗分支 / 超时 abort + fail_log 回放 |
| 合规 | 个人小号自用；L1 默认人工确认交互 |

## 附：玩法核查结论（v0.4 关键修正记录）

- ✅ 崩铁**无体力条**：冲刺无限，速度两档常数 → duration 线性可靠，删除了"体力耗尽失真"复杂度（S2 降级）。
- ✅ 无攀爬 → 路线为路径图：move 段上限 8s + milestone 半程校验（S5）。
- ✅ 第三人称自由视角 → heading 朝向校正（S1，最大玩法缺口）。
- ✅ 小地图宝箱图标 = 已收集权威信号 → verify.minimap / 跳过逻辑 / 探索度 OCR（S3/S4）。
- ✅ 任务宝箱依赖任务进度 → prerequisite 探测 + dialogue 态复用 autoplot（A6/A7）。
