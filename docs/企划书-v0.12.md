## 〇、解冻声明（Architecture Freeze 1.0 → Engineering Evolution 1.0）

v0.11 冻结期暴露了真问题：**架构全部正确，但点击链路连一次真机成功都没有**。根因不是设计，是执行层没有真正站在 March7th 的肩膀上——自造坐标换算（DPI 乘法错误）、绕开 March7th 官方原语（relative=True 直点窗口内坐标）、自建前台截图链路（March7th 默认 PrintWindow 后台截图）。

因此解冻，但**解冻有边界**：

**解冻（允许）**：执行链路修复 / March7th 桥接层 / 输入抽象 / 验证设施 / 失败检查 / 文档与规则修订。

**仍冻结（禁止）**：新 chest 类型 / 新地图算法 / 自动战斗 / Puzzle Solver / VLM Agent 化 / 更复杂导航 / 房间内部目标散布图 / 坐标编辑器 / GUI 美化。

判断标准（v0.11 附录 F.3 不变）：

> 它是在提高系统对**世界状态的理解**，还是在提高系统**隐藏自动化行为的能力**？后者拒绝。

## 一、核心决策：执行层 = March7th 原生 API（v0.12 最重要变更）

**决策**：WorldExecutor 执行器**不再实现任何输入/截图/坐标原语**，全部动作基于 March7th 官方 API 一步完成。March7th 就是我们的"操作系统"。

### 1.1 原语映射（源码确认）

| March7th 官方 API | 内部行为（automation.py 源码） | WorldExecutor 动作 |
|---|---|---|
| `auto.click_element(path, "image", threshold, max_retries)` | find_image_element → 中心点 → pyautogui.click(绝对坐标) | interact_template（宝箱/传送点/按钮） |
| `auto.click_element(text, "text", include, max_retries, crop)` | 截图 → OCR → 文字框中心 → 点击 | click_text（UI 操作，新增） |
| `auto.find_element(path, "image", threshold, max_retries=1)` | 截图 → 模板匹配 → 绝对坐标 | verify_signal（图标消失/出现） |
| `auto.take_screenshot()` | PrintWindow 后台截图 + screenshot_pos 换算基准 | VLM 观测帧来源 |
| `auto.press_key(key, wait_time)` | pyautogui.keyDown/Up | 移动/按键（visual guided move） |

### 1.2 坐标体系（修正历史错误）

- **执行器不感知 relative / DPI / scale_factor**。March7th 内部保证：截图内坐标 + `screenshot_pos`（客户区左上角绝对屏幕坐标）= 绝对坐标；>1920px 截图由 `screenshot_scale_factor` 归一化。
- **禁止执行器自算坐标换算**。v0.11 附录 C.3 的"relative=True 归一化坐标 + 自算屏幕坐标"路线**废止**——那是踩坑根源（click_test 的 `lx * 1.25` DPI 乘法把点击点推出 25%）。
- crop 参数遵循 March7th 任务惯例：**1920x1080 基准归一化**（`231.0/1920, 420.0/1080`），见 tasks/challenge/purefiction.py 等 100+ 处调用。
- VLM 定位输出 0-1000 归一化 → 仍由决策层转绝对坐标后走 `backend.click`（VLM 通道不进模板链路）。

### 1.3 与防腐层（附录 D）的关系

- March7th 是**外部引擎**，不属于 runtime/ 内部模块：只有 `runtime/input/march7th_backend.py`（桥接层）可以 import `module.automation`。
- 桥接层职责：封装 auto 原语 → 统一的 `InputResult(success/error/backend)`；未来换引擎只改桥接层。
- 冻结依赖链不变：`knowledge → compiler → runtime → api/events → studio/gui`。

## 三、Runtime Health / Capability Check（Review 落地 2）

启动即查五通道，任一 FAIL 提前 pause，不再盲目跑：

| 通道 | 检查内容 | 失败典型原因 |

- 实施：`runtime/health.py` + GUI 后台线程。

## 四、Observation Temporal Stability（Review 落地 4，升级 C.1）

单帧观测无意义（loading/镜头转动/UI 动画/粒子）。v0.11 附录 C.1 的"secondary confirmation"升级为**时间稳定性采样**：

```json
{
  "observer": "vlm_vision",
  "target": "chest",
  "confidence": 0.92,
  "temporal": { "samples": 3, "stable": true, "consistency": 1.0, "reads": ["absent","absent","absent"] }
}
```

- `sample_stability(capture_fn, observe_fn, samples=3, interval=2.5)`：连续独立观测，主决策值占比 ≥75% 才 stable。
- **`not found` 单帧永远不产生状态**；`opened` 必须 temporal.stable（C.1 三态判定升级版）。
- VLM 观测仍是纯观测通道（不产步骤、不参与执行决策，v0.11 铁律不变）。

## 五、Failure Inspector + Deterministic Failure Replay（Review 落地 5 + M1 验收补充）

### 5.1 Failure Inspector（GUI）

指挥台新增失败检查器卡片，回答"为什么失败"：

```
Run #003  FAILED
State: INTERACTING
Last observation: chest confidence 0.87
Action: click:chest_A.png
Input: march7th ✗
Reason: uipi_block → 建议: 重启并以管理员身份运行
```

失败来源：`action_executed.success=false`（输入失败）或 `target_progress.status=failed`（目标失败）。

### 5.2 M1 验收补充：Deterministic Failure Replay

v0.11 的 Deterministic Replay Check 只覆盖成功路径，补充失败路径：

- 同一知识包、同一失败场景执行 ≥2 次，Replay diff 必须能回答：
  - 失败点是否**逐动作一致**（same action / different observation = 观测漂移；different action / same observation = 决策漂移）。
- 判定：`same failure path ≤ 1 步偏差` 视为确定性失败，可进入修复；否则先修漂移源（时序/观测）。

## 六、March7th 集成硬事实（源码确认，固化防回踩）

1. **提权是前提**：`app.py` 用 `pyuac.runAsAdmin(False)` 整体提权；非管理员时 SendInput 被 UIPI 拦截（ret=0、pyautogui 光标不动）。March7th 没有特殊注入技巧——**裸 pyautogui + 管理员**。
2. **cwd 约束**：`CONFIG_PATH="./config.yaml"` 相对路径 → 任何 import March7th 的进程必须 `os.chdir(March7thAssistant 根)`。
3. **后台截图默认开**：`use_background_screenshot: true` → PrintWindow 后台截图，**不要求窗口前台**（前台 mss 链路为历史错误，废弃）。
4. **双实例窗口 bug（March7th 自带）**：`get_window` 取第一个 title 匹配的窗口，若用户环境存在隐藏 0x0 实例会踩中 → WorldExecutor 用自建 `find_game_window`（枚举可见窗口取最大客户区）前置校验，多实例直接 pause。
5. **pylnk3 安全事件固化**：`module/config/__init__.py` 含混淆 payload（防破解/免责校验，非窃取）；一律 stub 绕过（smoke/live_probe/live_monitor/click_test/校准脚本），**永不安装真包**。
6. **60s 截图重试坑**：`take_screenshot` 找不到窗口会空转 60s 后抛 RuntimeError → 调用前先 `find_game_window` 快速失败。
7. **模板体系**：模板图进入 March7th `scale_and_match_template`（1920x1080 基准匹配），黑塔模板按此裁剪制作。
