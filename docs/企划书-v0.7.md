## 〇、v0.7 核心定性

> 崩铁宝箱自动化的本质不是"看懂地图"，而是**维护一个可执行的世界状态图**。

- 地图 = **房间状态图**（Room State Graph），不是坐标空间、也不只是导航图。
- 门/电梯/传送点 = **Portal**（带状态的边）。
- 解谜/机关 = **离线生成解法**，运行时只执行不推理。
- VLM 只产**事件描述**，不产步骤；图边/步骤由规则+人工生成。
- 运行时零 VLM、零角度依赖（视觉目标驱动）。

## 四、房间状态图 + Portal System（本次核心）

### 4.1 Portal（替代普通 edge）

```json
// entities/portals.json
{
  "id": "door_A",
  "from": "corridor_A",
  "to": "sealed_room",
  "type": "door",                      // door|elevator|teleport|gate
  "states": [
    { "name": "locked", "condition": "quest_research=false" },
    { "name": "open",   "condition": "quest_research=true" }
  ],
  "arrival": [                          // 过门判定
    { "type": "landmark", "id": "lm_door_a" }
  ]
}
```

- 无状态的门 = 单 state 的 portal（简写省略 states）。
- 电梯/传送点 = 特殊 portal 类型，过门动作是"交互→加载"。
- 图搜索（Dijkstra/A*）只走 `当前 world_state 下可通行的 portal`。

### 4.2 Room State Graph

```
区域 → 房间(Room，区域=节点) → Portal(带状态边) → 房间
```

节点不是点，是区域（Room）；移动的结束 = arrival 条件达成（§五）。

### 4.3 spatial_hint（仅辅助，不作导航依据）

```json
{
  "id": "room_001",
  "semantic": "blacktower_base_corridor",
  "spatial_hint": { "minimap_x": 123, "minimap_y": 56 }
}
```

用途：小地图定位、地图截图匹配、路线编辑器、人工修包。删除位置作为导航依据的决定不变。

## 五、move 协议：目标区域 + 到达条件

```json
{
  "type": "move",
  "data": {
    "target": "corridor_A",
    "arrival": [
      { "type": "landmark", "id": "door_A" },
      { "type": "area",     "id": "corridor_A_zone", "image": "templates/zone_a.png" }
    ],
    "max_time_s": 12,
    "speed": "sprint",
    "fallback": "milestone"
  }
}
```

- duration 仅是执行参数；真正的语义是"进入目标区域/看到目标物"。
- 一条 arrival 满足即到达；超时未满足 → fallback（milestone 重校准）→ recovery。

## 六、相机协议：Heading Checkpoint（删角度依赖）

```json
{ "type": "camera",
  "mode": "heading",
  "data": { "target": "templates/see_door_a.png", "max_rotate_s": 6 } }
```

- **视觉目标驱动**：转到"看到模板目标"为止，不做 yaw/pitch 数值控制。
- 动作序列 = "看到门 → 面向门 → 前进"（landmark 视觉伺服 + move）。
- `mode:"rotate"` 仅保留为极少数兜底场景。

## 七、chest_type（8 类）

```
normal              # 普通箱
puzzle              # 解谜机关（走 Puzzle Executor）
monster_lock        # 战斗后出现
quest_unlock        # 任务后出现
daily_refresh       # 每日刷新/限时物
npc_interaction     # NPC 互动触发
environment_trigger # 环境触发
dynamic_trigger     # 跟随/追踪类（触发→目标移动→跟随→奖励，非常规 workflow）
```

每类对应不同 verify 与前置策略。

## 八、Puzzle Executor（离线生成解法，运行时零推理）

```
Chest Workflow → Puzzle Task → Puzzle Solver（离线，入库时生成）
```

```json
{ "type": "puzzle",
  "solver": {
    "kind": "rotation",                // rotation|light_path|push_block|path_link|...
    "state":  [0, 1, 2, 3],
    "goal":   [1, 1, 0, 2],
    "solution": ["click_piece_2", "click_piece_4", "click_piece_1"]  // 离线求解产物
  },
  "verify": { "secondary": { "image": "templates/puzzle_done.png" } } }
```

- solver 种类白名单：首批 rotation；其余 kind 标 `not_supported` 走人工。
- 运行时 = 按 solution 列表执行点击 + verify，无推理。

## 九、战斗分级（L2 安全性）

| 类型 | 判定 | 策略 |
|---|---|---|
| `combat_random` | 明雷普通遇敌 | 自动战斗（允许 L2） |
| `combat_required` | 任务/锁怪战 | **人工**（L2 中止等确认） |
| `combat_script` | 攻略里固定流程的战斗 | 按脚本执行 |

- 三者统一走 EVENT_INTERRUPT；只有 random 可全自动续跑。

## 十、world_state 扩展：exploration_state

```json
// entities/world_states.json
{
  "quest_research":   { "type": "quest_done", "quest_id": "人非草木·其一" },
  "daily_vendor":     { "type": "daily_refresh", "note": "每日4点刷新" },
  "npc_present":      { "type": "npc_available", "npc": "阿兰" },
  "sealed_room_open": { "type": "environment_state",
                        "detector": { "kind": "door_visible",
                                      "image": "templates/door_open.png" } }
}
```

- 环境/探索状态（机关是否开启、NPC 是否移动、区域是否刷新）与任务状态同构。
- 门控探测：进入区域前跑 detector（模板匹配/OCR），失败 → `prerequisite_unmet` 跳过。

## 十一、失败分类矩阵

| 失败信号 | 分类 | 恢复 |
|---|---|---|
| arrival/landmark 失配 | `position` | back_landmark（最近房间锚点） |
| 目标连续 N 帧未命中 | `template` | 重截 → repair_log → 人工确认 |
| 战斗团灭/位置重置 | `position(respawn)` | respawn_route（传送锚点整段重跑） |
| 事件中断超时 | `interrupt` | 重探测事件类型 → 人工 |
| 世界状态探测失败 | `prerequisite` | 标 unmet 跳过 |
| portal 状态不符 | `state` | 重读 world_state → 重计划路线 |
| 其他/超时 | `unknown` | 中止 → 回放排查 |

## 十二、事件中断 EVENT_INTERRUPT（沿用 v0.6 横切状态）

```
NAVIGATING / INTERACTING / PUZZLE
        │ 检测到外部事件
        ▼
   EVENT_INTERRUPT
   ├── combat_random     （自动战斗 → 续跑）
   ├── combat_required   （暂停等人工）
   ├── combat_script     （按脚本）
   ├── dialogue          （detect_only 暂停；L2 可 autoplot）
   ├── cutscene          （等待演出结束）
   └── ui                （弹窗/结算：分类处理）
        ▼
   RESUME（回到断点状态继续）
```

## 十三、VLM 降权：只产事件描述

```
攻略视频 → 抽帧/字幕 → VLM → 事件描述文本（不产步骤、不产 move、不产 JSON）
    ↓
规则抽取 + 人工补全 → 图边(portal)/room/chest 定位
    ↓
Puzzle Solver（离线）→ workflow JSON
```

- VLM 输出示例（正确形态）：
  > "从传送点进入右侧走廊，经过蓝色门，宝箱位于终端设备旁。"
- 错误形态（禁止）："向前3秒，右转30度"。
- 规则/人工负责把描述翻译成 graph edge + move + arrival。

```

   ↓ pass

   ↓                                                    │

   ↓                                                    │
VERIFYING（多信号 primary/secondary/tertiary）          │
   ↓                                                    │
INTERACTING ────────────────────────────────────────────┤
   ↓                                                    ▼
DONE ◄────────────────────────────────── EVENT_INTERRUPT
   （combat/dialogue/cutscene/ui）→ RESUME
   RECOVERING（fail：分类→恢复→回断点；portal/state 不符 → 重计划）
```

## 十五、Evaluation System（沿用 + state 指标）

| 指标 | 目标 | 测量 |
|---|---|---|
| Step success rate | move ≥95% / click ≥98% / verify ≥95% | statistics 按 step_type |
| Task success rate | 10 箱 ≥80% | route 级聚合 |
| Recovery success rate | ≥50% | fail_log + 恢复结果 |
| Interrupt 处理率 | ≥80% | EVENT_INTERRUPT 记录 |
| Portal/state 正确率 | ≥95% | state 级探测记录 |
| Knowledge confidence | min ≥0.6 可自动 | 多维置信度 |
| Human intervention | 每路线 ≤1 次 | repair_log 计数 |
| Time per chest | ≤90s（L1） | statistics.avg_time_s |
