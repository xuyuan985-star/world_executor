## 二、GUI State ≠ Runtime State（显示边界铁律）

- runtime 状态机冻结（11 态，含内部态），GUI 显示层压缩（8 主状态 + overlay 事件）。
- 未来 runtime 可能出现 `NAVIGATING_EDGE / MOVEMENT_CORRECTION / LANDMARK_SEARCH` 等内部态，GUI 一律映射到 NAVIGATING。
- **GUI 是人看的，不是调试全部状态**；全部状态进 Replay，不全进界面。

## 三、Runtime Replay 提前至 M0（v0.10 最重要新增）

Replay 不是 GUI 功能，是**调试基础设施**。第一批就定义统一事件：

```
runtime/events/
  schema.py     # 事件类型 + 字段定义（冻结）
  bus.py        # 事件总线（线程安全，可订阅/持久化）
```

事件 schema（冻结）：

```json
{
  "id": "evt_001",
  "execution_id": "run001",
  "time": 12345,
  "type": "state_changed",
  "from": "NAVIGATING",
  "to": "RECOVERING",
  "context": {
    "room": "corridor_A",
    "portal": "door_B",
    "reason": "arrival_failed"
  }
}
```

事件类型（首批冻结）：

| type | 说明 |
|---|---|
| `run_started` / `run_finished` | 会话生命周期 |
| `state_changed` | 状态迁移（from/to/context） |
| `observation` | 观测记录（见 §四 Observation Contract） |
| `action_executed` | 步骤执行（move/click/portal/…） |
| `target_progress` | 目标队列进度（target_id/status） |
| `fail_recorded` / `repair_recorded` | fail_log / repair_log 镜像 |

- 事件总线落盘 → runtime.db（events 表），GUI 只是**播放器**。
- Replay 数据生成在 M0（dry_run + 真机共用同一总线），GUI-M0.1 只显示实时流，M0.3 做回放界面。

## 四、修正 1：Observation Contract（冻结格式）

所有视觉/观测结果**必须**进入统一格式，禁止各自打印/各自记录：

```json
{
  "observer": "template_match",
  "target": "door_A",
  "confidence": 0.91,
  "timestamp": 123456,
  "context": {
    "room": "corridor_A",
    "world_state": "quest_done"
  }
}
```

契约字段（冻结）：

- `observer`：template_match / ocr / ui_signal / inferred / manual
- `target`：观测对象（door_A / in_combat / menu_open / room_id …）
- `confidence`：0~1（inferred/manual 允许 null）
- `timestamp`：毫秒
- `context`：room / world_state / portal 等环境快照（可选）

runtime/db.py 的 `record_state_observation` 改为按此契约写入；所有模板/OCR 调用点统一走 `observer` 通道。

## 五、修正 2：Knowledge 目录规范（compiler 输出不可手改）

```
knowledge/
  raw/        # 上游素材：视频事件清单、VLM 输出（只读输入）
  source/     # 手写/人工确认的源知识（人可改）
  compiled/   # compiler 产物（禁止手改，validator 强制检查生成者标记）
  patches/    # 补丁层：运行时 repair 的落盘补丁（优先级最高）
```

- `compiled/` 内文件带生成者标记（`"generated_by": "compiler-v0.1", "generated_at": ...`），validator 检测到"compiled 文件被手改"→ error。
- 优先级：patches > compiled > source。
- 现状迁移：`knowledge/black_tower_test` 为**手写测试包**，归属 source/（Sprint 0 不动结构，M0 compiler 上线时迁移目录）。

## 附录 B：Human-like Execution Policy（工程约束）

> 定位：不是规避检测模块，而是保证自动化行为符合正常用户操作范式。
> 原则：**降低机械化，不模拟外挂。** 本附录是执行器质量约束，不是能力模块。

### B.1 操作层随机化（Action Jitter）

禁止固定时间序列（`move 3000ms → sleep 500ms → click → sleep 1000ms`）；改为在合理区间内抖动：

```yaml
human_behavior:
  enabled: true
  delay:
    click:
      min_ms: 200
      max_ms: 800
    interaction:
      min_ms: 500
      max_ms: 1500
    transition_wait:
      jitter_ms: 1000
  movement:
    sprint_duration_variance: 0.15
    correction_interval_variance: 0.2
```

不追求随机，只消除完全固定的时间序列。

### B.2 移动行为约束（Movement Policy）

- 禁止：连续长距离完美直线 / 固定角速度旋转 / 每次停在完全相同位置。
- 允许：小幅方向修正 / 偶尔停顿 / 到目标附近提前减速。
- 实现：WASD 控制器前加 human movement filter（variance 见 B.1）。

### B.3 镜头行为限制（Camera Policy）

禁止 `yaw += 10°` 循环式机械扫描；保持 Heading Checkpoint（看到目标即停止旋转）。

```yaml
camera:
  max_continuous_rotate_s: 3
  search_pattern:
    - small_left
    - small_right
    - recenter
```

避免：无限扫描 / 高频左右抖动 / 完美角度锁定。

### B.4 行为节奏（Session Policy）

```yaml
session_policy:
  max_continuous_runtime_min: 60
  idle_break:
    enabled: true
    min_min: 3
    max_min: 10
```

用途：调试保护 / 防异常长时间运行 / 接近正常游戏节奏。

### B.5 错误处理策略（防无限重试）

```
fail → recover → 一次重新尝试 → 仍失败 → pause + human check
```

```yaml
recovery:
  max_retry:
    interaction: 2
    portal: 2
    movement: 3
  require_manual_after_limit: true
```

### B.6 日志增加 human_action 字段

```json
{
  "type": "action_executed",
  "action": "click",
  "target": "chest_01",
  "humanized": true,
  "delay_ms": 642
}
```

目的：分析失败 / 调整参数 / 对比自动化策略（不是隐藏行为）。

### B.7 L1/L2 安全等级调整

- **L1（默认）**：移动自动 / 镜头自动 / 交互确认 / 战斗人工 + `human_behavior=true`。
- **L2 = 高可信自动执行**（不叫"全自动"），要求：knowledge verified + confidence >0.8 + human_behavior enabled + 异常自动暂停。

### B.8 不做事项（防止跑偏）

❌ 随机鼠标轨迹生成器 / 模拟真人输入设备 / 反检测模块 / 行为对抗算法 / 绕过检测逻辑。
原因：会把项目从 World State Executor 变成自动化对抗系统，污染架构。

### B.9 落地时机

- M1 真机闭环前落地：Action Jitter + Movement/Camera Policy + Session Policy + 防无限重试（B.1~B.5）。
- B.6 随 runtime/events 已有 action_executed 扩展（加 humanized/delay_ms 字段，不新增事件类型）。
